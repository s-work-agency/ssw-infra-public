# 서비스 카탈로그

17개 모듈을 5개 그룹으로 나눠 운영합니다. 각 모듈은 **독립 저장소이자 배포 단위**이며, 동시에 하나의
완결된 모듈 구현 단위입니다 — 기능적으로 유용한 범용 모듈이면 스케일 트리거를 기다리지 않고 분리합니다.

분해 기준은 **도메인 능력(business capability)** 입니다. 기술 레이어 단위로 쪼개는 나노서비스는
안티패턴으로 명시적으로 경계했습니다.

**상태 표기**

| 표기 | 의미 |
|---|---|
| 🟢 라이브 | 쿠버네티스 클러스터에 배포돼 실사용 트래픽을 받는 중 |
| 🔵 개발 완료 | 구현·자동 검증 통과, 배포 대기 또는 배포 진행 중 |

## services — 직접 제품 기능

| 모듈 | 스택 | 역할 | 상태 |
|---|---|---|---|
| **auth-server** | Java / Spring Boot | 전 제품 공용 인증·계정. 사용자 JWT(RS256) 발급·갱신·폐기, JWKS 공개, 테넌트·역할 관리, 서버 간 서비스 토큰 발급, 게스트 단기 토큰. 인프라 신뢰 체계의 뿌리 | 🟢 라이브 |
| **file-server** | .NET | 파일 업로드·저장·서빙. 확장자·MIME·크기 검증, 테넌트별 저장 격리, 공개 파일 영구 URL과 비공개 서명 URL, 스토리지 백엔드 추상화(로컬 / S3 호환), 업로드와 같은 트랜잭션에 아웃박스 기록 | 🟢 라이브 |
| **media-server** | .NET Worker | 미디어 처리 전담. 업로드 이벤트를 구독해 리사이징·포맷 변환(WebP)·썸네일 파생본을 만들고 파일 API로 되돌려 저장. 저장(file)과 처리(media)를 분리해 각자 단일 책임 유지 | 🟢 라이브 |
| **notification-server** | Java / Spring Boot | 알림 발송 추상화 — 이메일·웹푸시·웹훅. 요청 즉시 202 후 내부 큐에서 발송·재시도, 테넌트별 템플릿, 발송 이력. 외부는 REST, 내부 서버는 이벤트 구독 두 경로 | 🟢 라이브 |
| **chat-server** | .NET / SignalR | 실시간 상담·문의 채팅. 테넌트별 룸 모델, 메시지 이력 REST, 로그인 사용자와 익명 게스트 동시 지원, 상담원 부재 시 알림 이벤트 위임 | 🔵 개발 완료 |
| **analytics-server** | .NET | 제품 이벤트 트래킹(미니 GA). 방문·페이지뷰·커스텀 이벤트 수집과 테넌트별 집계·리포트. 운영 로그(logging)와 다른 도메인 — 이쪽은 비즈니스 지표 | 🔵 개발 완료 |

## platform — 시스템 보조

| 모듈 | 스택 | 역할 | 상태 |
|---|---|---|---|
| **gateway-server** | Java / Spring Cloud Gateway | 단일 진입점. 경로 라우팅, WebSocket passthrough, 테넌트·IP 단위 레이트리밋, CORS 화이트리스트 일원화, 추적 ID 발급·전파, JWT 서명 검증과 신원 헤더 주입. 무상태 설계 — 재기동 즉시 복구 | 🟢 라이브 |
| **config-server** | Java / Spring Boot | 중앙 설정·피처플래그. 각 서버가 기동 시 pull + 주기 갱신, 변경 이력·롤백. 재배포 없이 설정 반영. 시크릿은 범위 밖(경계 명시) | 🔵 개발 완료 |
| **logging-server** | .NET Worker | 중앙 로그 수집·저장·조회. 내부 서버는 이벤트 구독, 제품 백엔드는 배치 push. 기간·레벨·서비스·테넌트·추적 ID 필터 조회. 수신은 fire-and-forget, 자기 로그는 로컬 파일만(순환 방지) | 🔵 개발 완료 |
| **monitoring-server** | Java / Spring WebFlux | 관측성 메트릭·가용성 축. 전 서버 헬스 엔드포인트 주기 폴링, 업/다운 이력, 다운·복구 시 알림 서비스로 즉시 통지. 대상 추가는 설정 변경만으로 | 🔵 개발 완료 |
| **tracing-server** | .NET | 분산 추적. OpenTelemetry(OTLP) 표준으로 스팬 수집, 추적 ID 기준 조회. 수집은 fire-and-forget이라 다운 시 추적 데이터만 유실되고 요청 처리는 무영향 | 🔵 개발 완료 |
| **scheduler-server** | Java / Spring Boot | 크론·배치 중앙화. 잡 정의·실행·이력·실패 통지를 한 곳에서. **로직은 대상 서버 API에 존재하고 scheduler는 트리거만** — 서버 경계를 지키기 위한 제약. 잡은 멱등 전제 | 🔵 개발 완료 |

> 관측성 3축(로그 · 메트릭/가용성 · 트레이스)을 **의도적으로 분리**하고, 세 축을 **추적 ID 하나로**
> 잇습니다. 한 서비스가 세 축을 다 하면 경계가 무너지고, 세 축이 서로를 모르면 교차 조회가 불가능합니다.

## apps — 클라이언트

| 모듈 | 스택 | 역할 | 상태 |
|---|---|---|---|
| **admin-web** | React · TypeScript · Vite · Zustand · Tailwind | 인프라 전체의 통합 관리 콘솔. 상태 대시보드 / 로그 뷰어 / 트레이스 뷰어 / 파일·미디어 브라우저 / 알림 템플릿·이력 / 채팅 상담원 콘솔 / 테넌트·토큰 관리 / 설정·피처플래그 / 잡 정의·이력 / 애널리틱스 리포트 | 🔵 개발 완료 |

설계 원칙 하나가 중요합니다 — **각 서버에는 관리 UI를 두지 않습니다.** 서버는 관리 API만 제공하고
UI는 전부 여기로 모읍니다. 새 인프라 서버가 추가되면 콘솔에 화면 모듈 하나를 더하는 구조입니다.
자체 도메인 DB 없이 전 데이터를 게이트웨이 경유 API로만 가져옵니다.

## core — 공유 계약 라이브러리

| 모듈 | 스택 | 역할 | 상태 |
|---|---|---|---|
| **core-java** | Java | Java 서비스용 공용 계약 — 이벤트 envelope·payload 타입, 오류 코드와 Problem Details 직렬화, 추적 ID 유틸리티, 공통 보안 컨텍스트 | 🟢 전 Java 서비스 소비 중 |
| **core-dotnet** | .NET | 위와 동일한 계약의 .NET 구현. 두 런타임이 같은 계약을 각자 해석해 어긋나는 것을 막는 장치 | 🟢 전 .NET 서비스 소비 중 |

계약 자체의 정본은 언어 중립적인 **JSON Schema · 매니페스트 · golden fixture**이고, 두 라이브러리는
그 산출물입니다. 계약 검증 스크립트가 외부 패키지 없이 매니페스트·스키마·fixture 간 정합성을
교차 검사합니다.

## ops — 개발·운영 기반

| 모듈 | 내용 | 상태 |
|---|---|---|
| **dev-env** | 로컬 개발 스택(컨테이너 컴포즈)과 **쿠버네티스 매니페스트 일습**. 데이터·지원·서비스·진입 계층의 배포 순서, 시크릿 생성 스크립트, DB 변형 두 가지(클러스터 내부 / 외부), 리소스 예산과 프로브 설계, 트러블슈팅 실측 기록 | 🟢 라이브 클러스터 운영 |
| **message-broker** | 이벤트 백본 구성 — Kafka(KRaft 모드) 컨테이너 구성, 토픽·DLT 초기화, 보존·접근 제어 등 런타임 토폴로지. **스키마 사본은 갖지 않고** core 계약을 정본으로 참조 | 🟢 라이브 |

## 데이터·지원 계층

| 구성 요소 | 용도 |
|---|---|
| **MariaDB** | 서비스별 독립 데이터베이스 + 전용 계정. 물리 자원은 공유하되 데이터 경계·권한은 서비스 단위로 격리 |
| **Valkey** | 캐시 · 게이트웨이 레이트리밋 백엔드 |
| **Apache Kafka** | 이벤트 백본(KRaft 단일 노드 — 개발·데모 규모). 비즈니스 토픽마다 DLT 1:1 |
| **개발용 SMTP 싱크** | 로컬·개발 환경의 메일 수신 확인용. 운영에서는 실 릴레이로 교체 |
| **S3 호환 로컬 스토리지** | 개발 환경에서 S3 API를 재현하는 도구. 파일 서비스는 로컬 어댑터와 S3 어댑터 두 구현을 헥사고날 포트로 보유해 설정만으로 교체 |

## 채택 확정 · 대기 중인 모듈

역할·경계까지 확정하고 킥오프를 기다리는 것과, 재검토 트리거에 도달할 때까지 보류한 것을 구분해
관리합니다.

| 모듈 | 성격 | 상태 |
|---|---|---|
| **llm-gateway** | LLM API 호출 단일 창구 | 채택 확정 · 킥오프 대기 |
| **agent-gateway** | 인프라 기능(로그·메트릭·설정·잡·알림)을 MCP 프로토콜 도구로 노출하는 **AI 에이전트 전용 진입점**. gateway가 사람·앱용 진입점인 것과 대칭 — 게이트웨이 경유, 에이전트 인증, 도구 호출 감사 로그, 읽기/쓰기 권한 스코핑 | 채택 확정 · 선행 조건 대기 |
| comment · content · service-registry · webhook-hub · shortlink | 제안 5종 | 각자의 재검토 트리거 도달 시까지 보류 |

"제안했으나 보류"를 지운 목록이 아니라 **보류 사유와 재검토 조건을 붙여 남겨 둔 목록**으로 운영합니다 —
왜 안 만들었는지가 왜 만들었는지만큼 중요합니다.
